# matrix_solver — сравнение методов решения СЛАУ

Проект решает систему линейных алгебраических уравнений (СЛАУ) `A·x = b`
несколькими методами и сравнивает их по точности и скорости:

1. **SVD** — обратная (псевдообратная) матрица, собранная через SVD-разложение;
2. **Regul** — решение через симметричную регуляризацию (дополнение системы);
3. **Pinv** — псевдообратная матрица Мора — Пенроуза (`numpy.linalg.pinv`);
4. **Gauss** — прямой метод Гаусса с выбором главного элемента.

Для каждого метода считаются метрики качества (норма, абсолютные и
относительные отклонения) и время на `1000` решений; сводная таблица
записывается в `results/<имя>_test.txt`.

## Классы

### `Matrix` (`solver/matrix.py`) — методы решения СЛАУ

| Метод | Назначение |
|---|---|
| `svd_res(A, b)` | Разлагает `A = U·S·Vt`, строит обратную матрицу `Vtᵀ·S⁻¹·Uᵀ` (сингулярные значения ≤ 1e-4 считаются нулевыми) и возвращает её и решение `x`. |
| `regul(A, b, step)` | Симметричная регуляризация: система дополняется до квадратной `(2n+1)` системы (строки с единичной диагональю + симметричные столбцы, параметр `step` в правом нижнем блоке); решение — через `numpy.linalg.solve`, возвращаются первые `n+1` компонент. |
| `pinv_res(A, b)` | Решение через `numpy.linalg.pinv`; возвращает псевдообратную матрицу и `x`. |
| `calcul_param_svd(A, b, koef, index, base)` | Возмущает `index`-ю компоненту правой части на `koef`, перерешивает задачу методом SVD и по приросту решения восстанавливает столбец обратной матрицы. |
| `invert_svd(A, b, koef)` | По `calcul_param_svd` поочерёдно возмущает каждую компоненту правой части и собирает обратную (псевдообратную) матрицу целиком. |
| `calcul_param_regul(...)`, `invert_regul(A, b, koef, step)` | То же, что и для SVD, но опорное и возмущённые решения находятся методом `regul`. |
| `VEDELEMENT(a, b, n, k)` | Выбор главного элемента: среди строк `k..n-1` находит максимальный по модулю элемент в столбце `k-1` и обменивает строку (в матрице и в правой части). |
| `GAUSSN(A, b, n)` | Метод Гаусса: прямой ход с `VEDELEMENT` и обратный ход. Векторизованная (NumPy) реализация исходного скалярного алгоритма; матрица копируется — исходный `A` не изменяется. |

### `Files` (`solver/files.py`) — ввод/вывод

| Метод | Назначение |
|---|---|
| `read(name)` | Читает `name.lst`: матрицу `A` (списком ненулевых элементов по узлам), правую часть `B`, эталонное решение `X` и эталонную правую часть `B_base`. Нумерация в файле — с 1. |
| `write(name, mass_data, title)` | Записывает сводную таблицу `mass_data` (столбцы: метод, метрики, время) в `name.txt` с заголовком `title`. |

Формат `*.lst` (см. также докстринг `Files`):

```
<имя> N              # N — число узлов (последнее число строки)
<x+1> <B[x]> <k>     # узел: номер, значение правой части, число ненулевых
<y+1> <A[x][y]>      #   k строк с ненулевыми элементами строки
d D                  # число D эталонных строк
<i+1> <B_base[i]> <X[i]>   # эталонная правая часть и эталонное решение
```

### `Metric` (`solver/metric.py`) — метрики качества

| Метод | Назначение |
|---|---|
| `discrepancy(base, result)` | Разность `base - result` (остаток). |
| `normal(vector)` | Евклидова норма вектора. |
| `max_absolute(base, result)` | Максимальное абсолютное отклонение. |
| `max_relative(base, result)` | Максимальное относительное отклонение (с нулями в `base` не считается). |
| `min_relative(base, result)` | Минимальное относительное отклонение. |
| `avg_relative(base, result)` | Среднее относительное отклонение. |

Все расчёты — в `float64`; результаты дублируются в атрибуты объекта
(`self.disc`, `self.norm`, `self.max_abs`, ...).

### `Test` (`solver/test.py`) — организация сравнения

| Метод | Назначение |
|---|---|
| `metric_stat(B, B_base)` | Считает и печатает сводку метрик (`Metric`) и возвращает её кортеж. |
| `_evaluate_method(name, solver, A, b, mass_metric, n)` | Прогон одного метода: решение, метрики качества, замер времени на `n` повторений; результат добавляется в сводную таблицу. |
| `run(name_r, name_w, step, regul_param)` | Полный цикл: чтение задачи (`Files`), контроль исходных данных (ранг, `A·X`), прогон всех четырёх методов (`Matrix`) и запись таблицы в `name_w.txt`. |

## Файлы данных

В `data/` лежат синтетические задачи — 2D Пуассон с пяти-точечной схемой
(матрица: 4 на диагонали, -1 у соседей по кресту), точное решение —
произведение синусов, «измеренная» правая часть отличается от эталонной
малым шумом:

* `frund_18_21.lst` — решётка 18×21 (378 узлов);
* `frund_21_21.lst` — решётка 21×21 (441 узел);
* `frund.lst` — решётка 10×10 (100 узлов).

Перегенерировать данные:

```bash
python scripts/generate_data.py
```

## Запуск

```bash
pip install -r requirements.txt
python main.py
```

Вывод — в терминал, таблицы результатов — в `results/<имя>_test.txt`
(столбцы: метод, норма, max abs, max rel, min rel, avg rel, время).

## Примечания по переработке исходного скрипта

Логика и названия методов сохранены; исправлено/доработано:

* кодировка исходника (был нечитаемый cp1251) — комментарии и вывод переведены в UTF-8;
* `def init` заменён на `def __init__` (конструкторы `Matrix`, `Files`, `Metric`
  в исходнике фактически не вызывались);
* `svd_res`: формула обратной матрицы приведена к общему виду `Vtᵀ·S⁻¹·U�T`
  (в исходнике была транспонирована — на симметричных матрицах, как в тестовых
  данных, результат одинаков);
* `GAUSSN`: матрица копируется — в исходнике через `np.reshape` алгоритм
  изменял исходный `A` на месте, из-за чего `A @ X` после Гаусса считался
  по уже преобразованной матрице;
* внутренняя итерация `GAUSSN` векторизована NumPy (скалярный вариант
  O(n³) в циклах Python занимал часы на решётках ~21×21), алгоритм и
  выбор главного элемента не изменены;
* код разбит на пакет `solver/`, добавлены `main.py`, генератор данных
  и таблица из 7 столбцов (в заголовке — 5 полей исходного скрипта).
